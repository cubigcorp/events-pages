# event-page — 같은 기준으로 페이지 작업하기

규칙 정본은 저장소 루트 `CLAUDE.md`입니다. 이 스킬은 그 순서를 빠짐없이 밟게 하는 체크리스트입니다. 사용자에게는 쉬운 말로 진행 상황을 알려 주세요.

## 1. 시작
- [ ] `git checkout main && git pull`
- [ ] 무슨 일인지 확인: 새 페이지 / 기존 페이지 수정 / 섹션 추가 / 새 양식 (애매하면 묻기)
- [ ] 새 브랜치: 새 페이지 = 폴더 이름, 수정 = `fix-폴더이름`

## 2. 필요한 정보 받기 (없으면 묻기, 지어내지 않기)
- 행사·방송 이름, 날짜(현지), 장소 또는 채널, 폴더 이름(영어 소문자·숫자·하이픈)
- 양식: On the floor(`exhibition`) / On stage(`stage`) / On air(`live`)
- 사진: 우리 팀 사진·보도자료 이미지가 없으면 CLAUDE.md §6-2 조건으로 찾기
- 한국어판은 항상 같이 만듦(국문·영문 전용 없음), 검색 노출(다가오는 행사 = 켬이 기본)
- 신청 폼이 있으면 HubSpot 삽입 코드, 미팅 예약 링크
- 숫자·고객 이름·로고·Gartner·인용을 넣는다면 팩트시트 확인 여부 (확인 안 됐으면 넣지 않고 PR에 '확인 필요')

## 3. 작업 (CLAUDE.md 해당 절)
- 새 페이지 → §3: §2 틀 페이지 복사 → 그 행사 내용으로 교체 → `events.json` 한 줄 → `sitemap.xml` → 메인 배너를 바꿀지 행사 담당자에게 묻기
- 디자인 페이지가 아직 없으면 → `events.json` 한 줄 + `python3 tools/make_basic_pages.py` (영·한 기본 페이지·page 칸·sitemap 자동)
- 다른 행사 카드·버튼 줄 정리 → `python3 tools/upgrade_detail_v2.py <폴더이름>`
- 섹션 추가 → §4: "이 페이지에만 / 다음 행사에도" 먼저 묻기
- 새 양식 → §5: 기존 양식+섹션으로 안 되는지 먼저 확인, 다섯 가지를 한 PR에
- 고치지 않을 것 → §7 (CNAME·⑤ 추적 코드·검색 설정·공통 파일 무단 수정)

## 4. 끝내기 전
- [ ] `python3 tools/page_seo.py <폴더이름>` (검색용 JSON-LD·x-default — 디자인 페이지를 새로 넣었거나 events.json·설명·대표 사진을 바꿨을 때)
- [ ] `python3 tools/check_pages.py` 오류 0건
- [ ] `python3 -m http.server 8090` (저장소 루트) → 데스크톱 1440px·모바일 375px 확인, 스크린샷
- [ ] 문구: 제품 이름 표기, 금지 표현, 영어 문구에 엠대시·큰따옴표 없음 (CLAUDE.md §11)
- [ ] 한국어판: CLAUDE.md §11-1 표기표·라벨·시제·영어판과 같은 사실
- [ ] 커밋 → `git push -u origin <브랜치>` → `gh pr create` (본문 = PR 체크리스트 + 스크린샷)

## 5. 사용자에게 보고 (CLAUDE.md §12)
- 공개 예정 주소, PR 링크, 검사 결과, 확인한 것·못 한 것, 사람이 정할 것
- 합치기(merge)는 마케팅팀 승인 뒤에만. Claude가 합치지 않습니다.
