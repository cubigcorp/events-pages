# events.cubig.ai

CUBIG 행사·캠페인 페이지 저장소입니다. 이 저장소의 `main` 브랜치에 올라간 파일이 그대로 **https://events.cubig.ai** 에 게시됩니다.

> **처음이라면 2번(Claude로 시작하기)부터 보세요.** 누가 작업하든 같은 기준으로 만들어지도록 규칙·템플릿·자동 검사가 준비돼 있습니다.

---

## 1. 처음이라면: GitHub 용어 5개

| 용어 | 뜻 |
|---|---|
| 저장소(Repository) | 페이지 파일을 모아 두는 공용 폴더. 지금 보고 있는 이 곳 |
| 커밋(Commit) | '저장'. 무엇을 바꿨는지 한 줄 메모와 함께 기록됨 |
| 브랜치(Branch) | 원본을 건드리지 않고 작업하는 사본. `main`이 실제 게시본 |
| 풀 리퀘스트(Pull Request, PR) | '내 사본을 게시본에 합쳐 주세요'라는 요청. 검토 후 합치면 게시됨 |
| GitHub Pages | 저장소 파일을 웹사이트로 보여 주는 기능. events.cubig.ai가 이것 |

> **`main`에 들어가면 1분 안팎으로 바로 공개됩니다.** 그래서 직접 `main`에 저장하지 않고, 브랜치에서 작업한 뒤 PR로 올립니다(아래 3번).

## 3. 구조와 양식

```
events-pages/
├─ index.html             ← events.cubig.ai 첫 화면 (행사 허브 cubig.ai/events/로 넘김, 건드리지 않음)
├─ CNAME · .nojekyll      ← 주소·설정 파일 (절대 수정·삭제 금지)
├─ CLAUDE.md              ← Claude가 따르는 작업 규칙 (수정은 마케팅팀 검토 후)
├─ events.json            ← 행사 목록 정본 (이벤트 페이지 메인 cubig.ai/events·메뉴·전체 목록이 읽음)
├─ sitemap.xml · robots.txt · 404.html
├─ assets/                ← 공통 파일: 바탕·머리글·바닥글·양식별 스타일 (모든 페이지에 반영)
├─ (틀 페이지)           ← 새 페이지는 같은 양식의 기존 페이지를 복사 (3번 양식 표)
├─ websummit-2026/        ← 페이지 폴더 (폴더 하나 = 페이지 하나)
│   ├─ index.html         ← 페이지 본문 (파일 이름은 꼭 index.html)
│   └─ hero.webp          ← 이 페이지에서만 쓰는 이미지
├─ ko/websummit-2026/     ← 같은 페이지의 한국어판
├─ meet/                  ← 옛 미팅 주소(cubig.ai/events/meet/ 로 넘김)
├─ tools/                 ← 검사 도구(check_pages.py)·기본 페이지 생성(make_basic_pages.py)·검색용 행사 정보(page_seo.py)·공홈 머리글 가져오기 등
└─ .claude/               ← 팀 공용 Claude Code 설정 (모두 같은 순서로 일하게 함)
```

- 폴더 이름이 곧 주소입니다. `webinar-1201/` → `https://events.cubig.ai/webinar-1201/`
- 폴더 이름 규칙: **영어 소문자·숫자·하이픈(-)만**, 띄어쓰기·한글·대문자 ❌ (예: `ai-summit-ny-2026`)

**양식 (페이지 종류마다 하나)**

| 양식 | 언제 | 틀 |
|---|---|---|
| On the floor (`exhibition`) | 컨퍼런스 부스, 전시 참가 | `websummit-2026/` · `oracle-ai-world-2026/` (짧은 기록은 `vivatech-2025/`) |
| On stage (`stage`) | 피칭, 발표, 데모데이, 수상, 선정 | `t-challenge-2026/` |
| On air (`live`, 한국어 '라이브 방송') | 크리에이터 라이브·인터뷰·방송 영상 | `alex-wang-2026/` |

- 새 페이지는 같은 양식의 **틀 페이지를 복사**해서 그 행사 내용으로 바꿉니다.
- 디자인 페이지를 아직 못 만들었으면 events.json 한 줄만 넣고 `python3 tools/make_basic_pages.py` 로 영·한 기본 페이지를 먼저 엽니다(나중에 디자인 페이지로 덮어씀). 모든 행사는 영·한 상세 페이지가 다 있어야 합니다.

- 새 양식이 필요하면(예: 웨비나 신청) 먼저 기존 양식에 섹션만 추가해서 되는지 보고, 안 되면 `CLAUDE.md` §5 절차로 만듭니다.

**섹션 추가**
- 이번 페이지에만 쓰는 섹션: 그 페이지 안에서 자유롭게 (공통 파일은 건드리지 않음)

## 4. 웹 화면만으로 올리기 (Claude 없이)

1. 저장소 첫 화면에서 3번 양식 표의 틀 페이지 폴더 → `index.html` 을 열고, 오른쪽 위 **Copy raw file**(복사 아이콘)로 내용을 복사합니다.
2. 저장소 첫 화면 → **Add file → Create new file**
3. 파일 이름 칸에 `폴더이름/index.html` 을 입력합니다(슬래시를 치면 폴더가 생깁니다).
4. 복사한 틀을 붙여 넣고 맨 위 체크리스트대로 고칩니다.
5. 오른쪽 위 **Commit changes** → **Create a new branch for this commit and start a pull request** → 브랜치 이름은 폴더 이름과 같게 → **Propose changes**
6. **Create pull request** 를 누르고, 슬랙으로 검토 요청을 알립니다.
7. 검토가 끝나 PR이 합쳐지면(Merge) 1분 안팎으로 공개됩니다.

이미지 올리기: 페이지 폴더로 들어가서 **Add file → Upload files** → 5번과 같이 새 브랜치 + PR.
고칠 때: 파일 열기 → 연필(Edit) → 수정 → 5번과 같이 새 브랜치 + PR.
`events.json`·`sitemap.xml` 추가는 웹 화면에서 하기 번거로우면 PR에 '목록 추가 필요'라고 적어 주세요.

## 5. 자동 검사

PR을 올리면 GitHub가 자동으로 검사합니다(PR 화면 아래 **Page check**). Claude Code는 PR 전에 같은 검사(`python3 tools/check_pages.py`)를 먼저 돌립니다.

| 결과 | 뜻 |
|---|---|
| ✅ 초록 | 통과 |
| ❌ 빨강 | 고쳐야 하는 오류가 있음. **빨간불이면 승인해도 합쳐지지 않습니다.** **Details** 를 누르면 무엇이 문제인지 한국어로 나옵니다 |
| ⚠️ 경고 | 통과는 했지만 확인할 것(공통 파일 변경, 큰 이미지 등) |

검사 항목: ⑤ 추적 코드 · 다른 추적 코드 추가 여부 · 검색 설정(canonical·사이트맵·noindex·x-default) · 검색용 행사 정보(JSON-LD Event) · 설명 길이 · 허브 카드 사진 = 상세 대표 사진 · 자리표시 남음 · 제품 링크의 UTM · 예약 링크 종료일 · 제품 이름 표기 · 이미지 크기 · `events.json` 형식 · 키·토큰처럼 보이는 문자열 · 공통 파일 변경

## 6. 주의사항

**공개 저장소입니다**
- 이 저장소의 모든 파일과 수정 기록은 누구나 볼 수 있습니다.
- **올리는(push) 순간 공개됩니다.** 브랜치에 올린 초안도 저장소에서 바로 보이고, **나중에 지워도 수정 기록에 남습니다.** 발표 전인 행사·캠페인 초안은 공개해도 되는 시점에 올려 주세요.
- 넣지 말 것
  - API 비밀 키, 폼 서비스의 비공개 토큰, 비밀번호 (GA4 측정 ID·GTM 컨테이너 ID는 공개돼도 괜찮습니다)
  - 리드 목록·참석자 명단 같은 고객 데이터, 고객 실명·연락처
  - 내부 문서·회의 메모, 미공개 가격·계약 내용
  - 원본 디자인 파일(.fig·.psd·.ai)
- 실수로 위 내용을 올렸다면 지우지 말고 먼저 마케팅팀에 알려 주세요. 지워도 기록에 남아 있어서 키 교체 같은 조치가 따로 필요합니다.

**건드리지 말 것**
- `CNAME`(지우면 events.cubig.ai 연결이 끊김), `.nojekyll`, 루트 `index.html`, `.github/`·`.claude/`·`tools/`(규칙·검사 설정)
- 이미 공개된 페이지의 폴더 이름 변경·삭제: 광고·메일에 걸린 링크가 깨집니다. 내릴 때는 먼저 알려 주세요.

**파일**
- 한 파일 100MB 초과 업로드 불가. 영상은 YouTube 등에 올리고 페이지에 넣어 주세요.
- 이미지는 가능하면 1MB 이하(.webp·.jpg 권장)로 줄여 주세요. 페이지가 느려집니다.

**검색 노출**
- **다가오는 행사 페이지는 검색에 나옵니다**(틀 기본값). 'CUBIG Web Summit'처럼 행사 이름으로 찾는 사람이 우리 페이지를 찾을 수 있습니다.
- 그래서 제목·설명·첫 제목에 **행사 이름·날짜·장소**를 넣고, 제품 설명은 짧게 쓴 뒤 공홈(cubig.ai) 페이지로 링크해 주세요. 공홈 문구를 길게 그대로 옮기면 공홈과 같은 검색어에서 순위가 갈립니다.
- 행사가 끝난 뒤에도 검색에 남길지는 마케팅팀이 정합니다. 끄려면 페이지에 noindex 줄을 넣으면 되고, 링크로는 계속 열립니다.
- 검색에 나오는 페이지는 `sitemap.xml`에 주소가 들어 있어야 합니다(Claude가 같이 처리).

**문구·디자인**
- 회사 메시지 기준(CUBIG Bible)에 맞는지 검토 후 공개합니다. 제품 이름 표기: `Syntitan`, `LLM Capsule`, `DTS`
- 한국어판은 `CLAUDE.md` §11-1 한국어판 쓰기 규칙을 따릅니다(합니다체, 지명은 한국어·제품과 행사 이름은 영어, 정해진 표기·라벨, 영어판과 같은 사실). 영어판을 그대로 옮기지 않습니다.
- 숫자·고객 성과·고객 이름·로고·인증·수상은 회사 팩트시트에서 외부 사용이 확인된 것만 씁니다. Gartner는 로고 그림 대신 글자 `Gartner®` 로 씁니다.
- 행사가 끝나면 '예정'으로 쓴 정보(부스 안내·행사 기간 예약 링크)는 빼 주세요. AI 검색이 지난 일정을 현재 정보로 가져갈 수 있습니다.

**추적(GA4)**
- 틀 페이지의 ⑤ 자리에 GA4 추적 코드가 이미 들어 있습니다. 방문·유입 경로는 자동으로 잡힙니다. 지우거나 다른 추적 코드를 추가하지 마세요.
- 미팅 신청·현장 미팅·메일·제품 링크·PDF 클릭은 공통 파일(`assets/ev-nav.js`)이 셉니다. cubig.ai로 가는 링크는 같은 사이트라 '외부 링크 클릭'으로 잡히지 않고, PDF 자동 측정도 꺼져 있어서 이 코드가 대신 셉니다.
- 버튼 모양·위치를 바꾸거나 새로 세고 싶은 행동이 있으면 마케팅팀에 알려 주세요.

## 7. UTM 규칙 (회사 UTM 운영 가이드 기준)

**한 줄 판단: 이 링크를 누르기 전에 사람이 CUBIG 사이트 밖에 있나요?** 예 → UTM 붙임 / 아니오 → UTM 붙이지 않음.

| 링크 | UTM | 예시 |
|---|---|---|
| 메일·SNS·QR·광고 → 이벤트 페이지 | **붙임** | 아래 예시 |
| 이벤트 페이지 → Syntitan·LLM Capsule·cubig.ai | **붙이지 않음** | `https://syntitan.ai/` 그대로 |
| 이벤트 페이지 → 다른 이벤트 페이지 | **붙이지 않음** | |

- 이벤트 페이지(events.cubig.ai)도 CUBIG 사이트입니다. 페이지 안의 제품 버튼에 UTM을 붙이면, 방문자가 원래 들어온 경로(메일·QR·SNS)가 덮여서 지워집니다. 제품으로 넘어간 건 GA4가 자동으로 이어서 셉니다.

**붙이는 값 (모두 영문 소문자, 단어 사이는 하이픈)**

| 파라미터 | 무엇 | 값 |
|---|---|---|
| `utm_source` | 어디서 | `linkedin` · `x` · `youtube` · `outbound`(아웃바운드 메일) · 행사 주최·장소 이름(QR) |
| `utm_medium` | 어떤 방식 | `social` · `video` · `email` · `offline`(행사 QR·인쇄물) · `referral` |
| `utm_campaign` | 어떤 행사 | 행사 폴더 이름과 같게(예: `websummit-2026`) |
| `utm_content` | 같은 행사 안의 구분(선택) | `qr-booth` · `invite-mail-1` · `ceo-post` |

예시
```
메일 초대장:   https://events.cubig.ai/webinar-1201/?utm_source=outbound&utm_medium=email&utm_campaign=webinar-1201&utm_content=invite-mail-1
부스 QR:       https://events.cubig.ai/websummit-2026/?utm_source=websummit&utm_medium=offline&utm_campaign=websummit-2026&utm_content=qr-booth
LinkedIn 게시: https://events.cubig.ai/webinar-1201/?utm_source=linkedin&utm_medium=social&utm_campaign=webinar-1201&utm_content=ceo-post
```

- `utm_term`은 쓰지 않습니다(검색광고 전용).
- 사람 이름·주차로 campaign을 만들지 않습니다.
- QR은 인쇄 전에 휴대폰으로 찍어서 주소창에 UTM이 그대로 남는지 확인합니다.

## 8. 신청 폼 넣기 (HubSpot)

폼은 직접 만들지 말고 **HubSpot 폼을 삽입**합니다. 제출 내용이 바로 HubSpot 연락처로 들어가기 때문입니다.

1. HubSpot → **Marketing → Forms**에서 폼을 만들거나 기존 폼을 고릅니다. 폼 이름은 행사 폴더 이름을 넣어 구분합니다(예: `[Event] webinar-1201 registration`).
2. 개인정보 동의 문구를 켜 둡니다(폼 설정의 데이터 개인정보 보호·동의 옵션). 유럽 방문자도 들어오는 페이지입니다.
3. 제출 뒤 동작을 정합니다: 감사 문구 표시 또는 감사 페이지로 이동.
4. 폼을 게시(Publish)한 뒤 **Share → Embed code**를 눌러 나오는 코드를 **그대로 복사**합니다. 코드를 직접 고치거나 새로 쓰지 않습니다.
5. 페이지 본문의 폼이 들어갈 자리(틀의 신청 폼 주석 위치)에 붙여 넣고, 로컬 미리보기에서 폼이 보이는지·제출이 되는지 확인합니다. 테스트 제출은 HubSpot에서 지워 주세요.
6. PR에 '신청 폼 있음 + 폼 이름'을 적어 주세요. 마케팅팀이 GA4에서 신청 완료를 셀 수 있게 설정합니다.

- 폼 삽입 코드 안의 계정 번호(portal ID)·폼 ID는 공개돼도 괜찮습니다. HubSpot 로그인 정보·API 키는 절대 넣지 않습니다.

## 8-1. 미팅 예약 링크 (Google 예약 페이지)

- 예약 페이지는 **crm@cubig.ai 공용 계정에서** 행사별로 만듭니다. 개인 계정으로 만든 링크는 넣지 않습니다(휴가·퇴사 시 끊김).
  - 이름: `[Event] 행사이름 · 부스 미팅`
  - 공동 호스트: 그 행사 담당자. '빈 시간 확인'에는 꼭 필요한 1~2명 캘린더만 연결합니다(연결한 캘린더가 모두 비어야 시간이 열림)
  - 예약 가능 기간: 행사 날짜로 설정
- 페이지에는 그 행사 예약 링크를 바로 넣습니다. 행사가 끝나면 **events.json 의 end(없으면 start) 다음 날부터** 버튼이 상시 30분 미팅 페이지(`https://cubig.ai/events/meet/`)로 자동으로 바뀌고, 예약 화면은 숨겨집니다(`assets/ev-nav.js`). 기본 틀 페이지의 현장 미팅 버튼은 숨겨지고 옆의 온라인 미팅 링크만 남습니다. 버튼에 따로 날짜를 적지 않아도 됩니다. 다른 날짜로 끊고 싶을 때만 `data-booking-until="YYYY-MM-DD"`를 적습니다.
- 상시 30분 미팅(공통 예약 링크): https://calendar.app.google/oCAQAos8bo4denCr7 — 미팅 신청 페이지(`https://cubig.ai/events/meet/`, 공홈 테마)에 들어갑니다. 행사가 끝나면 버튼이 이쪽으로 바뀝니다.
- 예약은 HubSpot에 자동으로 들어가지 않습니다(캘린더 연결 안 함). 예약자 정보는 crm@ 캘린더 예약 일정에서 확인합니다.
