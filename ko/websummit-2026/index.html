42%2025년 AI 이니셔티브 대부분을 중단한 기업 비율입니다. 1년 전에는 17%였습니다.

5.7시간데이터 분석가가 매주 데이터 준비와 정제에 쓰는 시간입니다.
  1. 01

    Use Case가 바뀌면 데이터도 다시 맞춰야 합니다.

    업무마다 필드, 형식, 규칙이 달라 준비 작업을 매번 새로 합니다.

  2. 02

    어떤 데이터는 그대로 쓸 수 없습니다.

    민감한 값은 옮길 수 없고, 정작 중요한 사례는 수십 건에 그칩니다.

  3. 03

    결과가 틀려도 원인을 알 수 없습니다.

    모델 문제일까요, 데이터 문제일까요? 평가 조건이 같지 않으면 가려낼 수 없습니다.

  4. 04

    하나만 바뀌어도 전부 다시 확인해야 합니다.

    데이터, 모델, 정책이 새로 바뀌면 무엇이 여전히 유효하고 무엇을 다시 확인해야 하는지 알기 어렵습니다.

Syntitan이 AI 업무에 맞게 데이터를 준비하는 방식입니다.

외부 LLM 활용

민감한 값은 외부 LLM으로 보낼 수 없었습니다. 질의 전에 대체값으로 바꾸고, 응답 후 내부에서 복원했습니다.

이 밖에 삼성증권 이탈 예측에서는 옮길 수 없던 계열사 데이터를 작업용 데이터셋으로 만들었습니다(2025년 우수상). CJ프레시웨이 견적서 초안 작성에서는 메뉴, 레시피, 상품 정보를 하나의 데이터셋으로 합쳤습니다. F1은 CUBIG이 측정했습니다(실제 데이터 vs. 실제 데이터 + DTS로 준비한 데이터). 기업명은 승인을 받아 표기했습니다.

AI-Ready Data Platform

Use Case마다 데이터를 점검·준비·검증하고, 결과마다 해당 데이터 Version을 남깁니다. 파일럿은 잘 됐지만 그 데이터를 아직 실제 운영에 믿고 쓰기 어려울 때 적합합니다.

Syntitan
 Data Enablement for AI

민감 데이터 제약이 있거나 드문 사례가 부족해 쓰기 어려운 데이터를 진단하고, AI 업무에 필요한 데이터 후보를 채웁니다. 중요한 사례가 너무 적거나 데이터를 그대로 쓸 수 없을 때 적합합니다.

DTS
 Context-Preserving Data Layer for AI

기록이 외부 LLM이나 RAG로 가기 전에 민감한 값을 맥락이 살아 있는 대체값으로 바꾸고, 결과에서 원래 업무 값으로 복원합니다. 기록을 LLM에 그대로 보낼 수 없을 때 적합합니다.

LLM Capsule

금융, 통신, 유통 분야 기업이 함께하고 있습니다.

Europe에서는 결과가 어떻게 나왔는지까지 보여줄 수 있어야 합니다.

판정마다 남는 Version 기록은 EU AI Act가 요구하는 질문에 답할 때도 도움이 됩니다. 적용 범위는 해마다 넓어지며, 고위험 시스템은 2027년 12월 2일부터 적용됩니다.

  1. Q1

    이 결과는 어떤 데이터에서 나왔을까요?

    최신 테이블이 아니라, 결과를 확인할 때 썼던 바로 그 Version이어야 합니다.

  2. Q2

    확인한 뒤 무엇이 바뀌었을까요?

    데이터, 모델, 정책이 바뀌면 어떤 점검 항목이 영향을 받는지 짚을 수 있어야 합니다.

  3. Q3

    같은 결과를 다시 보여줄 수 있을까요?

    결과만큼 중요한 게 그 결과를 만든 조건과 데이터 Version입니다.
